# 后端架构设计 —— 离别疗愈 AI 陪伴产品

> 一句话定位:**这是一个"记忆驱动 + 情绪感知"的多 Agent 陪伴系统。**
> 所有功能(深度访谈、日常陪伴、定期报告、树洞、纪念生成、模拟电话)本质都是围绕同一个
> **用户记忆系统**的不同读/写/生成视图。因此架构的核心不是"接入一个 LLM",而是
> **如何让记忆随疗愈进程持续演化、并在正确时刻被正确召回**。
>
> **文本模型约定:按延迟/质量分两级路由**——
> **冷路径**(报告/反思沉淀/状态概括等,质量优先)走推理模型 `deepseek-v4-pro`;
> **热路径**(陪伴对话/访谈决策/情绪抽取/树洞匹配等,延迟优先)走 `deepseek-chat`。
> 二者经模型网关统一路由,后续可对特定高情感场景接 Claude 等作为升级或兜底。

---

## 0. 技术本质与设计原则

| 产品诉求 | 技术映射 |
|---|---|
| 访谈→画像→疗愈计划 (F1-2/3) | 有状态的访谈 Agent + 结构化抽取 + 人机协同(可编辑重生成) |
| 日常陪伴 / 情绪节点触发 (F2-1/2) | 记忆增强的情感对话 Agent + 定时/事件触发调度 |
| 心情记录 / 定期报告 (F2-3/4) | 情绪分类引擎 + 记忆流"反思/沉淀"批处理 |
| 树洞匹配回信 (F3) | 语义向量匹配 + 隐私隔离 |
| 抠图/小作文/声音/视频/模拟电话 (F4) | 多模态生成流水线(异步 Job) |
| NFC 实体卡 (F5) | 短链/深度链接解析 + 专属记忆空间 API |

**四条设计原则:**
1. **记忆是一等公民(Memory-first)**:先建记忆系统,再建 Agent。记忆要有"沉淀、去重、纠错、随时间衰减"的能力,而不是简单追加对话历史。
2. **人机协同(Human-in-the-loop)**:画像/疗愈计划/报告都允许用户修改后重新生成,系统以"草稿→确认→固化"推进。
3. **安全优先于体验**:哀伤场景必须有危机干预兜底 + 深度合成合规 + 心理边界(不越界当"医生")。
4. **Monolith-first,模块清晰**:先一个 Python 服务 + 明确边界,高并发/重计算部分可后拆。

## 2. 技术选型(含理由)

### 2.1 核心语言与框架
| 组件 | 选型 | 理由 |
|---|---|---|
| 主服务 | **Python 3.12 + FastAPI** | AI 生态全部在此(LangGraph/模型 SDK/音频库);异步 + SSE 流式原生友好 |
| Agent 编排 | **LangGraph**(图状态机 + checkpoint 持久化) | 访谈/报告是"有状态、多步、可恢复"流程,需要状态持久化与人机回填;备选:Agent SDK / Tool Runner 做更轻的 agentic loop |
| 任务队列 | **Celery + Redis**(简单任务)+ **Temporal**(长流程:多天访谈/多模态流水线) | 疗愈流程跨天、需幂等重试与可恢复;Temporal 适合 durable workflow |
| 定时/触发 | APScheduler/Celery Beat + 事件触发 | 提醒、定期报告、纪念日触发 |

### 2.2 存储
| 组件 | 选型 | 理由 |
|---|---|---|
| 主数据库 | **PostgreSQL 16**(MVP 阶段默认 SQLite,可切换) | 关系数据(用户/信件/订阅/订单) + JSONB 存画像 |
| 向量检索 | **pgvector** | 与 PG 同库,事务一致、运维简单;规模上来后可平滑迁 Milvus/Qdrant |
| 记忆图(可选) | **Neo4j**(或先用 PG 自建节点/边表) | 记忆的"实体—关系—情绪"图谱,先不做,验证需要再加 |
| 缓存/会话 | **Redis** | 会话态、限流、热记忆、发布订阅(树洞通知) |
| 对象存储 | **腾讯云 COS**(私有桶 + 预签名 URL;本地目录兜底跑通) | 音频、图片、视频、NFC 专属空间资源;备选阿里云 OSS / MinIO / R2 |

### 2.3 AI / 模型
| 用途 | 选型 | 说明 |
|---|---|---|
| 冷路径:报告 / 反思沉淀 / 状态概括(质量优先) | **`deepseek-v4-pro`** | 推理模型,产出长、需综合判断(阶段概括、趋势、卡片文案) |
| 热路径:陪伴对话 / 访谈决策 / 情绪抽取 / 树洞匹配(延迟优先) | **`deepseek-chat`** | 非推理,单轮结构化抽取/分类/短回复,低延迟 |
| 升级 / 兜底 | Claude、Qwen(经网关可路由) | 特定高情感场景或故障降级时切换;模型网关统一管理 |
| 文本情绪分类(可微调小模型) | 微调 BERT / emotion2vec 类 | 低延迟、低成本的兜底分类 |
| 语音识别 ASR | **FunASR / SenseVoice / Whisper** | 中文识别、情感顺带提取 |
| 声音克隆 TTS | **CosyVoice2 / GPT-SoVITS**(自建)· ElevenLabs/MiniMax(商用) | 亲人声音→鼓励录音,需 few-shot 声音克隆 |
| 抠图 | **SAM2 / rembg** | 物件数字化(F4-1) |
| 宠物 AI 视频 | **Wan2.1(开源)/ 可灵 / Runway / Vidu / CogVideoX** | 图生视频 |

> **模型网关是硬需求**:多供应商路由 + 按订阅档位分模型 + 超时降级 + token 计量(计费依据)+ 统一结构化输出。默认冷路径 `deepseek-v4-pro`、热路径 `deepseek-chat`,网关不锁死,便于后续升级。

## 3. 核心模块详细设计

### 3.1 记忆系统(重中之重)

参考 **MemGPT/Letta(记忆分层与自编辑)** + **Generative Agents(记忆流 + 反思沉淀)** 思想,设计如下:

```
┌────────────────────────────────────────────────────────────┐
│  Core Memory(核心记忆,始终注入 system prompt)               │
│  ├ 用户画像 user_portrait: 年龄/性别/失去类型 loss_type(breakup 分手 / loved_one 亲友离世[亲人+挚友] / pet 宠物) │
│  │   关系/时长/当前目标(忘记 vs 带着记忆走下去)/疗愈计划阶段   │
│  └ 对象画像 object_portrait: 姓名/昵称/关系/性格/共同记忆/     │
│      重要地点与时间/未说出口的话/声音语气特征                   │
├────────────────────────────────────────────────────────────┤
│  Semantic Memory(语义记忆,稳定事实,去重)                     │
│    从对话抽取的、被多次确认的事实(user 与 object 通用)         │
├────────────────────────────────────────────────────────────┤
│  Episodic Memory Stream(记忆流,带时间戳的事件)               │
│    每条: {type, ts, content, 抽取事实[], 情绪向量, importance, │
│            embedding, 地点/时间标签}                          │
├────────────────────────────────────────────────────────────┤
│  Emotional Nodes(情绪节点,反复出现的触发点)                   │
│    {trigger:"周六晚上", emotion:"想念", intensity, frequency, │
│     place, last_seen}   ← 由"反思"过程聚合而来                 │
└────────────────────────────────────────────────────────────┘
```

**三条核心流程:**

1. **写入(每轮对话后异步)**:LLM 抽取事实 + 情绪 + 显著性打分 → 追加记忆流;检测到冲突事实 → 标记并"以新盖旧"。
2. **召回(每次回答前)**:`score = α·recency(时间衰减) + β·importance + γ·relevance(余弦)` 混合检索;哀伤场景额外做 **时间衰减** 以刻画"最近是否走出来了"。
3. **反思/沉淀(定期批处理)**:从记忆流聚合生成情绪节点、趋势("你这周最难过总在晚上""三次提到同一个地方")、更新画像。这是 **F1-4 / F2-4 报告的数据来源**。

> 关键点:记忆是"**会进化的状态**",不是日志。疗愈计划(heal_plan)本身也是记忆的一部分,随报告更新。

### 3.2 Agent 编排层

用 LangGraph 定义状态机,每种业务一个图;工具层统一暴露给所有 Agent:

| Agent | 职责 | 关键设计 |
|---|---|---|
| 访谈 Agent (F1-2) | 轮询提问→回答→追问 | 结构化访谈提纲 + 基于"已涌现画像"动态追问;产出草稿画像 |
| 报告 Agent (F1-3) | 生成画像 + 疗愈计划 | 草稿→用户编辑→重生成(人机协同,循环直到确认) |
| 陪伴 Agent (F2-2) | 日常情感对话 | 注入 Core Memory + 召回相关记忆;每轮前置安全网关;语气按 loss_type + 主导情绪路由(安抚/引导) |
| 反思 Agent (F1-4/F2-4) | 后台沉淀记忆流→节点/趋势/报告 | 定时批处理,幂等 |
| 心情 Agent (F2-3) | 每日记录→分类打分→细节洞察 | 情绪分类 + 结合记忆生成"用户看不到的变化" |
| 树洞/匹配 Agent (F3) | 写信/回信/匹配 | 语义匹配 + 隐私隔离 |
| 纪念 Agent (F4) | 小作文/录音脚本/视频脚本/模拟电话脚本 | 强记忆锚定(昵称、语气、共同记忆),输出到生成引擎 |
| 安全 Agent | 危机检测/内容审核 | 每轮前后置,不可绕过 |

> 文本类 Agent 统一走 `deepseek-v4-pro`;对话/抽取/推理重任务靠系统提示与结构化输出区分,后续如需要再按任务分流。

**工具层(Agent 可调用):** `memory.search(query, filters)` / `memory.record(...)` / `memory.get_portrait(kind)` / `emotion.classify(text)` / `clock.now()`(时间感知,用于软引导) / `report.render(draft)` / `multimodal.submit(kind, payload)`。

### 3.3 情绪引擎

- **情绪分类(LLM 优先 + 词表兜底)**:主路径走 `deepseek-chat` 结构化输出到固定情感词表(难过/想念/焦虑/愤怒/释怀/平静 …)+ valence/arousal/score(0–100);LLM 不可用时用本地词表 `_lexicon_classify` 兜底。
- **危机检测(硬性安全闸门,零 LLM)**:关键词**硬匹配 + 否定守卫**(如"不想死"不触发、"撞死"触发),命中自伤/轻生语义 → 立即升级、推送心理援助热线、阻断并转人工提示。安全闸门不依赖 LLM,保证极端情况下仍可用。
- **打分与趋势**:离散情绪映射为 0-100 情绪分,按时间窗口聚合为状态指标(见 3.5 状态数据化),供报告与趋势。

### 3.4 语气路由(按失去类型)

陪伴对话每一轮先选「安抚型 SOOTHE / 引导型 GUIDE」两种语气基调,再生成回复:

- **输入**:近期情绪节点的主导情绪 + 情绪均分 + `loss_type`。
- **失去类型调制**(核心):`loved_one`(亲友离世)/`pet`(宠物离世)属**丧亲型**,默认更偏**安抚/陪伴**,避免急着"拉人往前走";`breakup`(分手)才更多走**引导向前**。→ 丧亲用户切"引导"的门槛更高(情绪均分阈值更高)。
- **急性情绪兜底**:主导情绪落在 {难过, 孤独, 焦虑, 恐惧, 愤怒} 时,无论 loss_type 一律安抚。
- 输出 `{tone, prompt 模板, reason}`,`reason` 可供前端/调试解释"为什么此刻这样陪伴"。

### 3.5 状态数据化(情绪 → 状态指标)

把记忆流里的情绪信号,按**时间窗口聚合**为可解释的状态(纯本地聚合,零 LLM):

- **基础指标**:近 7 天情绪均分 `baseline`、趋势 `trend`(后半段均值−前半段均值)、波动 `volatility`、急性情绪占比 `acute_ratio`、平静/释怀占比 `calm_ratio`。
- **和解度 `reconcile`(0–100)**:`0.35·平静占比 + 0.20·趋势 + 0.20·(1−急性占比) + 0.15·均分/100 + 0.10·目标加成`。
- **阶段 `stage`(5 级)**:`低谷期 → 波动期 → 趋稳期 → 平静期 → 和解期`,由基线/趋势/急性占比/平静占比/和解度联合判定(阈值暂用经验值,后续随真实数据调优)。
- **记忆点数据**(供报告选卡):活跃天数、最长连续倾诉、首次释怀日期、最常想起的时间/地点、深夜次数、提到 TA 次数、最难过的一天、最常选疗愈主题。
- 这些指标是**内部信号**,不直接把冷分数暴露给用户;只经报告/回信资格/语气路由消费。

### 3.6 定期跟踪报告(记忆点 · 滑动卡片)

事件触发:**数据充足(累积 ≥7 天且倾诉 ≥15 条)且用户打开时**生成;结构为**可快速翻完的滑动卡片流**。

- **因人而异**:卡片按"优先级 + 阶段门槛 + 数据是否可用 + 分线多样性"筛选,最多 `report_max_cards`(默认 6)张。低阶段看不到"释怀/回信/情绪演变"这类"往前走"的卡(避免像在催他好起来),和解期才出现里程碑卡(第一次释怀、想念→平静、回过信)。
- **记忆点优先**:具体有情绪画面的卡(最难过的那天、多少个夜晚、第一次释怀)排在通用计数卡(倾诉次数/陪伴天数)之前。
- **状态总括卡第一**:冷路径 `deepseek-v4-pro` 生成一句 ≤40 字的温柔概括。
- **对比上次**:每份报告把状态落 `StateSnapshot`,下次生成返回 `compared`(阶段升降 + 均分差)。

### 3.7 树洞信箱(F3)

**写信**(事件触发):使用满 `treehole_write_days`(暂定 3)天时,弹出窗口让用户写下痛苦/困惑。落库前抽取经历标签 + 摘要。

**回信**(事件触发):用户情绪长期稳定(累积天数 + 近 7 天均分达标 + 3 天内无急性情绪)或判断已**和解**后,匹配与其经历最相似的信:

- **匹配**:规则结构化初筛(失去类型 + 情绪标签 + 阶段)→ 取 top-k → LLM 复排 → 返回 top-n。
- **回信**:用户写回信 → 状态 `pending_review` → 审核通过后 `delivered` 给原信作者;用户也能收到别人给自己的回信。
- **隐私与安全**:信件/回信内容经 **PII 扫描**(正则硬匹配手机号/邮箱/身份证/地址/社交账号 + LLM 语义扫描人名/地名/单位),**不得包含任何真实定位与联系方式**;后台审核队列二次把关,匿名隔离防止二次伤害。

### 3.8 多模态生成流水线(异步 Job)

统一 Job 模型:`job {id, user, kind, input_ref, status, progress, result_ref, cost, watermark}`。
- **抠图数字化(F4-1)**:SAM2/rembg 分割 → 存透明底 + 元数据;"灰飞烟灭"效果主要由前端 WebGL/粒子 shader 实现(后端只提供素材)。
- **对方口吻小作文(F4-2)**:纯 LLM(`deepseek-v4-pro`),锚定 object_portrait 的语气/共同记忆。
- **亲人声音→鼓励录音(F4-3)**:ASR 提取→few-shot 声音克隆(CosyVoice2/GPT-SoVITS)→ 文案 LLM 生成鼓励语 → 合成,输出打水印。
- **宠物 AI 视频(F4-4)**:图生视频(Wan2.1/可灵),脚本由纪念 Agent 生成。
- **模拟前任电话(F4-5)**:LLM 生成"来电脚本"(含昵称等 memory 元素)→ 情感 TTS → 播放;若做实时语音对话,需 WebRTC + 低延迟 ASR/TTS 的 voice-agent 管线。

### 3.9 定时触发 / 提醒系统(F2-1)

- **触发源**:时间(Cron/纪念日)、情绪节点(命中"周六晚上"这类 trigger)、用户状态(熬夜提示)。
- **软引导文案生成**:陪伴 Agent 结合时间 + memory 生成,"你以前周六晚上总和他打电话,这周我们换个方式度过"。
- 订阅版 = "AI 主动触发",免费版 = 基础提醒,以此做功能分层。

## 4. 关键数据模型(核心表)

## 5. 关键实现技术(先进点)

1. **记忆自编辑与沉淀(MemGPT/Generative Agents 思想)**:分层记忆 + 周期性"反思"聚合,而非简单 RAG;实现记忆的去重、纠错、时间衰减。
2. **混合召回**:向量(语义) + 关键词 + 时间衰减 + 重要性加权;哀伤场景专门做"趋势召回"(判断用户是否在变好)。
3. **上下文缓存降本**:把 Core Memory 与系统提示放前缀以命中上下文缓存,多轮对话成本大幅下降;网关统一管理缓存策略。
4. **结构化输出**:画像/情绪/报告全部走 JSON Schema 强制,保证可写入 memory 与可渲染。
5. **有状态 Agent 编排(LangGraph checkpoint)**:访谈可中断恢复、报告可"人机回填循环"。
6. **Temporal 持久工作流**:多天访谈、多模态长任务的重试/幂等/可恢复。
7. **模型网关 + 成本计量**:`deepseek-v4-pro` 为默认文本模型,按 tier 路由、token 级计费(订阅与成本挂钩)、超时降级。
8. **few-shot 声音克隆 + 深度合成合规**:CosyVoice2/GPT-SoVITS,生成物打水印 + 显式告知。
9. **情绪时间序列 + 趋势挖掘**:把情绪数字化,支撑"用户看不到的变化"这一产品亮点。
10. **安全网关前置(不可绕过)**:危机检测 + 内容审核作为每轮对话的强制前后置。

## 6. 工程难点与对策

| 难点 | 说明 | 对策 |
|---|---|---|
| **记忆的"正确性"** | 对话事实会冲突、会过期、会被 AI 误解 | 结构化抽取 + confidence + 来源溯源 + "以新盖旧" + 用户可纠错 |
| **记忆的"演化"** | 用户是否真的走出来,需要跨时间判断 | 情绪时间序列 + 反思沉淀 + 趋势召回,而非只看最近一次 |
| **哀伤场景安全** | 危机干预 + 不越界当医生 + 二次伤害 | 安全 Agent 强前置 + 危机升级热线 + 内容边界/免责声明 + 可转专业咨询(2B) |
| **多轮长上下文成本/延迟** | 访谈/陪伴轮次长,Token 成本高 | 上下文缓存 + 记忆压缩(只注入 Core + 相关)+ 模型分级 |
| **声音克隆伦理/合规** | 克隆逝者声音敏感 | 深度合成规定合规:告知+水印+授权,身份信息(PIPL)最小化 |
| **多模态长任务** | 视频/声音生成耗时长、易失败 | 异步 Job 模型 + 进度/幂等/重试 + 成本上限熔断 |
| **树洞匹配质量** | 相似但不伤人的匹配难 | 语义 + 类型 + 阶段多维匹配 + 内容审核 + 匿名 |
| **"软引导"的时机** | 触发提醒要恰到好处不烦人 | 情绪节点 + 时间 + 频率控制(去重/限频)+ 订阅分层 |

## 7. 风险与合规

- **个人信息保护(PIPL)**:情感数据属敏感个人信息,需单独授权、最小化收集、可删除("被遗忘权")。
- **深度合成规定**:声音克隆、AI 视频必须打水印 + 显式告知,禁止未授权克隆他人(尤其逝者需家属授权)。
- **生成式 AI 办法**:内容标识 + 投诉举报入口。
- **心理边界**:明确"AI 陪伴 ≠ 心理治疗",危机时引导专业热线与医院(同时支撑 2B 学校/咨询所场景)。

## 8. 分阶段实现 Plan(建议路线图)

> **当前实现进度(2026-08)**:Phase 0/1 骨架已落地——FastAPI + SQLAlchemy(默认 SQLite,可切 PG/pgvector)、
> 模型网关(`deepseek-v4-pro` 冷 + `deepseek-chat` 热)、记忆系统(写入/召回/反思)、
> 情绪引擎(LLM 优先 + 词表兜底 + 危机否定守卫)、语气路由(loss_type 调制)、访谈、每日主题、情绪日历、
> 树洞信箱、状态数据化 + 定期跟踪报告均已跑通(可用 mock 脚本端到端模拟)。
> 待做:多模态(F4)、NFC(F5)、订阅计费、生产鉴权、真实数据阈值调优。

### Phase 0 — 地基(1–2 周)
- 仓库骨架(FastAPI + PG/pgvector + Redis + Celery)、CI、可观测骨架。
- 模型网关雏形(`deepseek-v4-pro` 为主 + 结构化输出 + 日志)。

### Phase 1 — 记忆系统 MVP(2–3 周)★ 最高优先级
- 记忆分层模型 + 写入/召回/反思三流程跑通。
- 情绪分类引擎 + 危机检测(至少关键词级)先行。
- 输出:一个能"记住并随时间更新用户画像"的底座。

### Phase 2 — 访谈 + 报告闭环(F1-1~F1-4)(2–3 周)
- 微信登录、访谈 Agent、画像/疗愈计划草稿→确认、报告生成。
- 打通"对话→memory 写入"完整链路。

### Phase 3 — 日常陪伴 + 情绪记录(F2)(2–3 周)
- 陪伴 Agent(SSE 流式)、每日心情、定时触发软引导、首个定期报告。

### Phase 4 — 树洞(F3)(1–2 周)
- 写信/匹配/回信,匿名 + 审核。

### Phase 5 — 纪念与告别(F4)(3–4 周,依赖外部模型/GPU)
- 抠图(可先行)→ 小作文 → 声音克隆 → 宠物视频 → 模拟电话。

### Phase 6 — 硬件 + 商业化 + 打磨(NFC F5、订阅计费、Eval、灰度)(持续)
- NFC 解析、订阅/计费、LLM 评估集、性能压测、合规上线。

> **建议落地顺序**:先 Phase 1 记忆系统 + Phase 2 访谈报告(这是产品不可替代的核心价值),再铺开陪伴、树洞、多模态。多模态中"声音克隆"是社媒爆点但合规最重,建议最后稳妥上线。
